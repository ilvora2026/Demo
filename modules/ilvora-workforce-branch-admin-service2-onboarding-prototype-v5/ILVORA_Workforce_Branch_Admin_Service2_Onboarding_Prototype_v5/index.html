Employee Enrolment – Existing Approved Employee

A separate enrolment workspace for completing the records of an employee whose onboarding application has already been approved and whose Employee ID has been generated.

This page does not create a new employee or generate an Employee ID. Use New Employee Onboarding for new applicants. Enrolment details are linked to the existing permanent Employee ID.

Demo only: files are selected in the browser and are not securely stored or transmitted.

Enrolment workflow

  • Branch Admin/HR retrieves an existing approved employee using the permanent Employee ID.
  • Branch Admin/HR completes personal contact, emergency contact and bank/payroll details.
  • Branch Admin/HR saves the enrolment record and prints it for physical signature/filing where required.
  • Completed details are submitted to Head Office for verification. Corrections are recorded with an audit trail.
  • Administrator-only fixed salary management remains in Salary Setup; this enrolment page cannot edit salary.

Production safeguards: verify Employee ID and branch assignment server-side; mask bank details except to authorised payroll users; encrypt data in transit and at rest; restrict document access; validate file types and scan uploads; maintain an audit trail; retain physical records under the approved schedule.

Employee Exit & System Access Control

Manage resignation and termination access separately. This workflow revokes login access; it does not delete the employee's employment or statutory records.

Resignation: employee login access is scheduled to be disabled automatically at the end of the approved last working day.

Access-control rules

  • Termination: only the Administrator can revoke system access. Branch Admin/HR may submit the case, but cannot perform the revocation.
  • Resignation: once the resignation and last working day are approved and recorded, the system automatically disables employee login access at the end of that date.
  • Preserve records: employee profile, attendance, payroll, leave, payslips, contracts and audit history remain archived according to the approved retention schedule.
  • Audit: retain who submitted and approved the exit, the last working day, access-disable timestamp, and Administrator action where applicable.

Prototype limitation: this screen simulates the workflow only. Real automatic deactivation requires a server-side scheduled job and identity-provider/session revocation. The production system must enforce Administrator permissions on the server, prevent self-approval, revoke active sessions/tokens, and retain records under the approved legal retention schedule.
