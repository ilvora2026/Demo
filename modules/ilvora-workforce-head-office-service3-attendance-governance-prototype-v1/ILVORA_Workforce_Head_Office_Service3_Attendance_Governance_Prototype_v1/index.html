Approval safeguards

  • Only Branch Admin / HR submits formal requests.
  • Attendance Operators cannot edit or submit formal corrections.
  • Requester cannot approve their own request.
  • Original punch and full audit history remain preserved.
  • Payroll-closed changes create adjustment workflow.
Decision flow: Employee reports discrepancy → Branch Admin / HR checks evidence and submits formal request → Head Office reviews → approve, reject or return → approved change updates attendance while preserving original punch → employee and Branch Admin / HR are notified.
Payroll closure: If the attendance period is already closed, approval must not silently rewrite a finalised payroll run. The system should create a traceable payroll adjustment item for authorised payroll processing.
Prototype limitation: Sample data and decisions are browser-only. No live attendance records, notifications, payroll linkage, authentication or backend audit store is connected. Production requires server-side authorisation, immutable audit logs, evidence storage and transaction-safe correction processing.
